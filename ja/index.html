マイクと Mac の音を、
1 本のマイクに。

自分の声と、Mac が再生している音——通話の相手の声、動画、なんでも——を ミックスして、どのアプリからでも選べる 1 つの入力デバイスとして見せます。

ダウンロード 仕組み

無料 · macOS 14.2 以降 · Apple silicon / Intel · Apple の署名・公証済み

できること

文字起こしツールや AI アシスタントが読むマイクは 1 本だけです。 自分ひとりが話しているうちは問題ありませんが、会話に相手がいる瞬間に行き詰まります。 スピーカーから出ている相手の声は、マイクの入力には入っていないからです。

Open Mic は Open Mic という入力デバイスを追加します。 マイクを選べる場所でこれを選ぶだけで、そのアプリに会話の両側が届きます。

  • 両方届いている。 左右のバーが動きます。
  • マイクだけ。 右が平らなまま＝システム音声が届いていません。
  • システム音声だけ。 左が平らなまま。

メーターを付けたのは、「動かない」の正体がたいてい片方だけの不調だからです。 左がマイク、右が Mac の音。どちらが止まっているのか、何も開かずに分かります。

メニューのスクリーンショット（準備中）

手順は 2 つ

  1. メニューバーから Open Mic を ON にする
  2. 使いたいアプリのマイクとして Open Mic を選ぶ

設定はこれだけです。出力デバイスには一切触らないので、 スピーカーもヘッドフォンも音量キーも、今までどおり動きます。

BlackHole などでは駄目なのか

BlackHole のようなツールはループバックデバイスです。 そこへ送った音が入力として返ってくる仕組みで、システム音声を自分で拾う機能も、 マイクと混ぜる機能もありません。近いことをやろうとすると、 自分でも音を聞くために「複数出力装置」を作り、システムの出力先をそれに変更し、 さらにマイクと組み合わせた「機器セット」を作ることになります。

それでも動きません。 機器セットは音源を 別々のチャンネルに並べるだけで（マイクが 1-2ch、ループバックが 3-4ch）、 合成はしません。ブラウザをはじめ多くのアプリは先頭 2 チャンネルしか読まないので、 届くのはマイクの音だけです。

Open Micループバック＋機器セット
1-2ch に合成音が来るはいいいえ（別チャンネル）
ブラウザや一般的なアプリで使えるはいマイクのみ
設定入れて ON にするだけ複数出力＋機器セットを手作業
出力デバイスを変更する必要なしあり（必須）
ヘッドフォンを替えても大丈夫かはいたいてい組み直し

向こうが優れている点もあります。実績があり、オープンソースで、 古い macOS でも動き、画面収録の権限も要りません。 Open Mic はそのぶん多くを要求する代わりに、この一点を自動でやります。

必要な権限

初めて ON にするとき、macOS が 2 つ確認します。

  • マイク — あなたの声を取得するため
  • 画面収録 — Mac が再生している音を取得するため
2 つ目に驚かれると思うので先に書きます。Open Mic は画面を録画しません。 macOS ではシステム音声の取り込みが「画面収録」の権限に含まれており、 これ以外に要求する手段がありません。使っているのは Core Audio の プロセスタップ API だけで、画面キャプチャの API には一切触れていません。

どこにも送信しません。ネットワーク通信のコードが存在せず、 音声はメモリ上を通るだけでディスクにも書きません。 リリースには セキュリティ担当者向けの資料を同梱していて、 ご自身で検証するためのコマンドも載せてあります。

インストールとアンインストール

.pkg をダウンロードして開くだけです。 Developer ID で署名され Apple の公証を通っているので、警告なく開けます。

インストール時に Core Audio が再起動するため、 Mac の音が 1〜2 秒途切れます。通話中は避けてください。

削除する場合

sudo "/Library/Application Support/OpenMic/uninstall.sh"

すべて削除したうえで、残存ファイルが無いことを検証して報告します。
